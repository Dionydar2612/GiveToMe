# Givetome

**สมุดบัญชีส่วนตัวที่เรียบง่าย — บันทึกรายรับรายจ่าย คุมงบ และวางแผนเงินในที่เดียว**

PWA ใช้งานบนมือถือและเดสก์ท็อป · หลายผู้ใช้ ข้อมูลแยกกันเด็ดขาด · ยอดเงินคำนวณจากรายการเสมอ

`Node.js` · `TypeScript` · `Express` · `PostgreSQL` · `Prisma` · `Vanilla JS PWA`

## ภาพรวม

Givetome ตอบโจทย์คนที่อยากรู้แค่ว่า **เงินเหลือเท่าไร จ่ายอะไรไปบ้าง และเดือนนี้มีบิลอะไรยังไม่จ่าย** โดยไม่ต้องเรียนรู้แอปการเงินที่ซับซ้อน
หน้าตาเน้นมินิมอล ใช้งานด้วยมือเดียวบนมือถือ รองรับโหมดมืด และติดตั้งเป็นแอปบนหน้าจอโฮมได้

### ฟีเจอร์หลัก

| หมวด | รายละเอียด |
|---|---|
| **บันทึกรายการ** | รายรับ รายจ่าย โอนระหว่างบัญชี พร้อมหมวดหมู่และโน้ต · แก้ไข/ยกเลิกได้ (ยกเลิกแล้วไม่ลบ มี audit log) |
| **หลายบัญชี** | เงินเดือน ใช้จ่าย เงินออม เงินสด กระเป๋าเงิน · กดบัญชีเพื่อดูรายการเดินบัญชีพร้อมยอดคงเหลือหลังแต่ละรายการ |
| **เช็คลิสต์รายเดือน** | บิลประจำสร้างรายการให้ทุกเดือน ติ๊กจ่ายได้ทั้งเต็มจำนวนและบางส่วน แก้ยอดเฉพาะเดือน ยกเลิกการจ่ายได้ |
| **เงินเดือนอัตโนมัติ** | ตั้งวันและจำนวนเงิน ระบบลงรายรับให้เมื่อถึงวัน แสดงรอบเงินเดือนและจำนวนวันที่เหลือ |
| **งบประมาณ** | ตั้งงบรายหมวด ดูความคืบหน้าและเตือนเมื่อใกล้เต็ม/เกินงบ |
| **เป้าหมายออม** | ผูกกับบัญชีออม ดูความคืบหน้าและฝากเงินเข้าเป้าหมายได้ในไม่กี่แตะ |
| **รายงาน** | สัดส่วนรายจ่ายตามหมวด รายจ่ายรายวัน แนวโน้มรายเดือน และ Export CSV |
| **ออฟไลน์อย่างปลอดภัย** | ขณะออฟไลน์จะ “บันทึกไม่ได้” พร้อมแจ้งเตือนชัดเจน และข้อมูลที่กรอกค้างไว้ไม่หาย |

## หลักการออกแบบ

- **ยอดเงินคำนวณจากรายการเสมอ** — ไม่เก็บยอดคงเหลือเป็นตัวเลขลอย ๆ และไม่รับยอดจาก Frontend ทำให้แก้ไข/ยกเลิกรายการแล้วยอดไม่เพี้ยน
- **เงินใช้ทศนิยมแม่นยำ** — ใช้ `decimal.js` และ `Decimal(14,2)` ในฐานข้อมูล ไม่มีปัญหา 0.1 + 0.2
- **ไม่นับโอนเป็นรายจ่าย** — เติมเงิน 220 ใช้ 60 รายจ่ายจริงคือ 60
- **กดซ้ำไม่เบิ้ล** — ทุกการบันทึกมี idempotency key (รวมถึงการติ๊กจ่ายบิลและการลงเงินเดือนอัตโนมัติ)
- **ไม่มีคิวเขียนออฟไลน์โดยเจตนา** — ข้อมูลการเงินต้องตรงกับเซิร์ฟเวอร์เสมอ จึงเลือกบล็อกการบันทึกแทนการเก็บคิวที่อาจชนกันภายหลัง
- **แยกข้อมูลตามผู้ใช้ทุก query** — ทุกการอ่าน/เขียนผูก `userId` และตรวจความเป็นเจ้าของบัญชีก่อนใช้งาน

## ความปลอดภัย

รหัสผ่านเก็บด้วย scrypt · เซสชันเป็น HttpOnly cookie ที่ลงลายมือชื่อ (`SameSite=Strict`, หมดอายุ 7 วัน) · จำกัดอัตราการสมัคร/เข้าสู่ระบบ · POST/PUT ต้องเป็น JSON (กัน CSRF) · Export CSV กัน formula injection · ปิดรับสมัครใหม่ได้ด้วย `ALLOW_SIGNUP=false`

## เริ่มต้นใช้งาน

**ต้องมี:** Node.js 20+ และ PostgreSQL

```bash
cp .env.example .env        # ตั้งค่า DATABASE_URL และ SESSION_SECRET
npm install
npx prisma db push          # สร้าง/อัปเดตตาราง
npm run build && node dist/server.js
```

เปิด http://localhost:3000 แล้วสมัครใช้งานได้ทันที

### ตัวแปรสภาพแวดล้อม

| ตัวแปร | จำเป็น | คำอธิบาย |
|---|:-:|---|
| `DATABASE_URL` | ✓ | สตริงเชื่อมต่อ PostgreSQL |
| `SESSION_SECRET` | ✓ (production) | ค่าสุ่มยาว ๆ สำหรับลงลายมือชื่อ cookie |
| `ALLOW_SIGNUP` | | ตั้งเป็น `false` เพื่อปิดรับสมัครใหม่ |
| `TEST_DATABASE_URL` | | ฐานข้อมูลทดสอบสำหรับเทสต์ API (ห้ามใช้ฐานข้อมูลจริง) |

## Deploy บน Render

1. Push โปรเจกต์ขึ้น GitHub (ห้าม commit `.env`)
2. Render → **New → Blueprint** → เลือก repo (ใช้ `render.yaml` สร้าง Web Service + PostgreSQL)
3. ตรวจ Environment: `DATABASE_URL` ผูกอัตโนมัติ · `SESSION_SECRET` สุ่มอัตโนมัติ · เพิ่ม `NODE_ENV=production`
4. Deploy — ตอนสตาร์ตระบบสร้าง/อัปเดตตารางให้เอง (เพิ่มอย่างเดียว ไม่ลบข้อมูลเดิม)
5. ตรวจที่ `/health` ต้องได้ `{"ok":true}`

> **หมายเหตุ:** แผนฟรีของ Postgres บน Render มีอายุจำกัดและไม่เหมาะเก็บข้อมูลจริงระยะยาว ควรใช้แผนที่มี backup และตรวจเงื่อนไขแผนปัจจุบันก่อนใช้งาน

## API โดยย่อ

ทุกเส้นทางยกเว้น `/health` และ `/api/auth/*` ต้องเข้าสู่ระบบ

| กลุ่ม | เส้นทาง |
|---|---|
| ผู้ใช้ | `POST /api/auth/register` · `login` · `logout` · `GET /api/me` |
| บัญชี | `GET/POST /api/accounts` · `PUT /api/accounts/:id` · `GET /api/accounts/:id/statement` |
| รายการ | `GET/POST /api/transactions` · `PUT/DELETE /api/transactions/:id` · `GET /api/categories` |
| เช็คลิสต์ | `GET/POST /api/checklist` · `PUT/DELETE /api/checklist/:id` · `POST …/:id/pay` · `POST …/:id/unpay` |
| บิลประจำ | `GET/POST /api/bill-templates` · `PUT/DELETE /api/bill-templates/:id` |
| เงินเดือน | `GET/PUT/DELETE /api/salary` · `GET /api/cycle` |
| งบ / เป้าหมาย | `GET/PUT /api/budgets` · `GET/POST /api/goals` · `PUT/DELETE /api/goals/:id` |
| รายงาน | `GET /api/summary` · `GET /api/reports/monthly` · `GET /api/export/transactions.csv` |

## การทดสอบ

```bash
npm test                    # เทสต์ตรรกะบัญชี รอบเงินเดือน งบ เป้าหมาย (รันได้ทันที)
```

เทสต์ API ครอบคลุมการแยกข้อมูลระหว่างผู้ใช้ การคำนวณยอด เช็คลิสต์ เงินเดือนอัตโนมัติ งบ และเป้าหมาย
ใช้ PostgreSQL จริงและจะถูกข้ามถ้าไม่ตั้งค่า `TEST_DATABASE_URL`:

```bash
TEST_DATABASE_URL=postgresql://user:pass@localhost:5432/givetome_test npx prisma db push
TEST_DATABASE_URL=postgresql://user:pass@localhost:5432/givetome_test npm test
```

## สำรองและกู้คืนข้อมูล

```bash
DATABASE_URL=... npm run backup                        # สร้างไฟล์ backups/givetome-<เวลา>.dump
DATABASE_URL=... ./scripts/restore.sh backups/<ไฟล์>.dump   # กู้คืน (ต้องพิมพ์ RESTORE ยืนยัน)
```

ตรวจความถูกต้องของไฟล์หลังสำรอง เก็บ 14 ไฟล์ล่าสุด (ปรับด้วย `KEEP`, `BACKUP_DIR`) ตั้งเวลาอัตโนมัติด้วย cron:

```cron
0 3 * * * cd /path/to/givetome && DATABASE_URL=... ./scripts/backup.sh >> backups/backup.log 2>&1
```

ต้องมี `pg_dump` / `pg_restore` (postgresql-client) · ไฟล์สำรองมีข้อมูลการเงินจริง เก็บในที่ปลอดภัย (`backups/` อยู่ใน `.gitignore`)

## ข้อจำกัดและแผนต่อไป

- ยังไม่มีรีเซ็ตรหัสผ่าน ยืนยันอีเมล และลบบัญชีด้วยตนเอง
- แก้ไขรายการได้เฉพาะจำนวนเงิน ชื่อ หมวด และโน้ต (เปลี่ยนบัญชี/วันที่ให้ยกเลิกแล้วบันทึกใหม่)
- เป้าหมายออมหลายอันที่ผูกบัญชีเดียวกันจะแสดงความคืบหน้าเท่ากัน
- ยังไม่มีการแจ้งเตือนบิลใกล้ครบกำหนด
